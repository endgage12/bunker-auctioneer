# «Раз, два, продано!» — веб-игра аукцион + покер

Многопользовательская веб-игра по мотивам события «Раз, два, продано!» из **Neverness to Everness**.
Полные правила — в [RULES.md](./RULES.md).

## Что внутри

- **Vue 3 + TypeScript + Tailwind CSS 4** (Vite) — клиент;
- **Node.js + Express + Socket.IO** — сервер с realtime-геймплеем;
- **SQLite** (встроенный node:sqlite, без внешних СУБД) — пользователи, предметы, история;
- **Google OAuth 2.0** — вход через Google-аккаунт (+ dev-вход для локальной разработки);
- **Игровой движок на чистом TypeScript** — доски, лоты, слепые ставки, раунды (юнит-тесты + E2E);
- **Барахолка (p2p-рынок)** — страница «Аукцион»: лоты по своей цене, комиссия дома 5%,
  продажа торговцу по номиналу предмета, отмена лотов, истечение через 7 дней;
- **Банк дома** — внутренний аккаунт-банк с журналом операций: доходы партий, комиссии, покупки
  торговца, стартовые капиталы и админ-панель (/admin) с пополнением, выплатами и продажей предметов дома;
- **Сеты** — страница «Сеты»: 9 тематических коллекций по 5 предметов (витрины),
  активные бонусы к торговле, барахолке и аукциону, суточная трансмутация алхимика;
- **Библиотека** — страница «Библиотека»: обучающий помощник с правилами, основами, каталогом
  предметов с описаниями и поиском с подсветкой совпадений;
- **Тайный Санта** — страница «Тайный Санта»: аналог «Ящика диких» из Таркова — предметы
  вкладываются безвозвратно, и через 15/30/60 секунд (в зависимости от суммы вложений)
  ящик приносит случайный дроп; чем дороже вложения, тем выше шанс редкого предмета;
- **Боты (живой онлайн)** — 44 самостоятельных ИИ-игрока с психологическими характерами:
  сами собирают лобби (в том числе 4 бота играют между собой), торгуются, торгуют на барахолке,
  собирают сеты, вкладываются в «Тайного Санту» и стремятся в топ-10 богатейших. У ботов **ровно
  те же правила, что у людей**: тот же стартовый набор, никаких читов и доступа к скрытому
  состоянию стола. Ожидание лобби для живого игрока — **не больше 30 секунд** (проверяется
  скриптом `npm run bots:sla`);

- **Магазин и особые карточки** — страница «Магазин» (/shop): колесо фортуны на GSAP
  (крутка 5 секунд, билет — 1 «Пыльная ваза») выдаёт карточки из комплектов «Анализаторы»
  (личное раскрытие редкости скрытых предметов стола — границы подсвечиваются цветом
  редкости) и «Усилители» (случайный предмет инвентаря становится синим/жёлтым/золотым/
  красным). Чем сильнее карточка, тем ниже шанс выпадения. Коллекция — в инвентаре.

### Ключевые механики

- При регистрации игрок получает **300 000 валюты**, случайный набор предметов на **~380 000**, 5 билетов колеса фортуны и 3 карточки «Малый анализатор редкости»;
- Предметы имеют размерность **N×M** (1..5 × 1..5), 7 редкостей (Белый → Красный);
- **Стол 12×16 формируется и запечатывается до ставок** (суммарная ценность предметов 300 000 – 9 000 000, дешёвые столы чаще; занято 50–95% клеток), лежат вплотную друг к другу от правого верхнего угла (сверху вниз, справа налево). Стоимость стола реально попадает в целевой диапазон: редкости подбираются по «цене за клетку», иначе дешёвых столов не существовало бы вовсе;
- **Вступительные ставки валютой** (30–100к) идут в банк дома и открывают участие в торгах;
- В начале все ячейки закрыты; с каждым раундом торгов открывается часть лота — видны предметы и **сумма их стоимости**;
- Аукцион до 5 раундов **слепых ставок** с множителями **×2 → ×1.6 → ×1.3 → ×1.1 → безусловно** (как в NTE);
- Ничья в 5-м раунде — дополнительный 6-й раунд; повторная ничья — лот не достаётся никому;
- **Ставку платит только победитель** — проигравшие её не теряют (их расход только вступительный взнос);
- Победитель аукциона платит свою ставку в банк и забирает все предметы стола. Если он в плюсе — остальные ничего не получают, но и не теряют; если в минусе — **каждый проигравший получает 10% от его минуса**;
- Итог игры = наличные + номинальная стоимость инвентаря; экономика персистится между партиями.

## Быстрый старт

Требуется **Node.js ≥ 22.5** (проверено на 24.x).

    npm install          # один раз, корень монорепо
    npm run dev          # сервер (http://localhost:3000) + веб (http://localhost:5173)

Откройте **http://localhost:5173** и войдите через **тестовый вход** (любой email) —
так можно играть без настройки Google OAuth. Откройте игру в нескольких вкладках/браузерах
с разными email, создайте комнату и поделитесь кодом.

Кроме тестового входа есть кнопка **«Войти как shlepafloppa»** — постоянный аккаунт с входом
по паролю (по умолчанию `zasq12`, меняется переменной `SHLEPAFLOPPA_PASSWORD`). Пароль
проверяется на сервере (`POST /api/auth/password-login`) и в клиентский бандл не попадает;
неудачные попытки throttl'ятся. Обе тестовые кнопки доступны только при `ALLOW_DEV_LOGIN=true`.

### Сборка для продакшена

    npm run build                              # соберёт apps/web/dist
    npm run start -w @auctioneer/server        # сервер раздаст и API, и статику

## Google OAuth

1. Откройте [Google Cloud Console](https://console.cloud.google.com/) → APIs & Services → Credentials →
   **Create credentials → OAuth client ID → Web application**.
2. Authorized redirect URIs: **http://localhost:3000/api/auth/google/callback** (или ваш домен).
3. Скопируйте .env.example в .env и заполните:

    API_ORIGIN=http://localhost:3000
    WEB_ORIGIN=http://localhost:5173
    GOOGLE_CLIENT_ID=ваш-client-id.apps.googleusercontent.com
    GOOGLE_CLIENT_SECRET=ваш-secret
    JWT_SECRET=случайная-строка

Сервер автоматически читает .env из корня проекта. После этого кнопка «Войти через Google»
работает: авторизация через OAuth2 code-flow, сессия — JWT на 7 дней.

## Инвентарь

Отдельная страница «Инвентарь» (/inventory) — тарковская сетка: ячейки 64×64 px,
**фиксированная сетка 12×24** (12 колонок, 24 строки), предмет занимает область N×M ячеек.
Если сетка заполнена, новые предметы не помещаются — покупки и трансмутация требуют свободного места,
а выданные автоматически предметы показываются в полосе «переполнение» под сеткой. Позиции предметов **сохраняются на сервере**, предметы
можно **перетаскивать (drag & drop)** — при занятом месте сервер отклоняет перемещение.
Есть поиск (от 2 символов; совпадения подсвечиваются золотой рамкой, остальное затемняется)
и кнопка «Автосортировка». Все пути получения предметов автоматически кладут их на свободные
ячейки. REST: POST /api/items/move, POST /api/items/sort.

У каждого предмета каталога есть **иконка 64×64** (сгенерированы нейросетью, лежат в
`apps/web/src/assets/items/{defId}.png`): в плитке предмета иконка — сверху по центру,
название — снизу под ней, при наведении всплывает popover с деталями (редкость, стоимость,
размер, номинал каталога). Перегенерация набора: `apps/image_generation/catalog_icons.py`
(нужен запущенный ComfyUI и его python_embeded с Pillow). Фавиконка (золотой молоток аукциона
в ударе) генерируется через тот же ComfyUI: `apps/image_generation/favicon_icon.py gen|finalize`.

## Игровой экран

Экран партии разбит на три части: слева — список игроков и их показатели в текущей игре,
в центре — **игровой стол 12×16** (ячейки 64×64 px; все клетки закрыты в начале игры,
на раскрытом предмете — всплывающая подсказка; сверху строка «Текущая ожидаемая стоимость
предметов на столе»), справа — блок **«Особые карточки»** (анализаторы применяются во время
торгов: границы случайных скрытых предметов подсвечиваются цветом их редкости — лично
для владельца), панель **вступительной ставки** (10–100к) и панель торгов.

Ядро — аукцион **«Корабль сокровищ»** по правилам NTE: весь стол разыгрывается одним аукционом
из 5 раундов (×2 → ×1.6 → ×1.3 → ×1.1 → безусловно), предметы раскрываются постепенно для всех
и не исчезают со стола, победитель забирает всё; при ничьей в 5-м раунде — 6-й раунд только
между лидерами, повторная ничья — без продажи; ставку платит только победитель, а при переплате
каждый проигравший получает 10% от его минуса.

## Магазин и особые карточки

Страница «Магазин» (/shop) — колесо фортуны: билет на крутку стоит **1 «Пыльную вазу»**,
колесо крутится **5 секунд** (анимация на **GSAP**) и выдаёт случайную карточку из набора.
Чем сильнее карточка, тем меньше шанс её выпадения (веса колеса: 30/16/10/4 % — анализаторы
от малого к совершенному; 20/12/6/2 % — усилители от синего к красному).

Два комплекта карточек:

- **«Анализаторы»** — личные карточки партии: малый/средний/большой/совершенный анализатор
  раскрывает редкость 2/4/6/8 случайных скрытых предметов стола; на доске их границы
  подсвечиваются цветом редкости — видит только владелец. Применяются в правой панели
  экрана партии во время торгов;
- **«Усилители»** — вне партии: случайный предмет инвентаря слабее цели превращается
  в случайный предмет синего/жёлтого/золотого/красного качества соответственно
  (нижние качеством предметы не затрагиваются; без цели карточка не сгорает).

Полученные карточки видны на странице «Инвентарь» под сеткой (усилители применяются там же).
REST: GET /api/shop, POST /api/shop/spin, GET /api/cards, POST /api/cards/amplify.

## Тайный Санта

Страница «Тайный Санта» (/santa) — аналог «Ящика диких» из Escape from Tarkov: слева инвентарь
игрока, справа ящик с сеткой **9×9** (ячейки 64×64, как в инвентаре), перенос предметов — drag & drop.
Предмет, перетащенный в ящик, вкладывается **безвозвратно** и виден в ящике с замком, пока идёт круг;
круг запускается после **минимум 3 вложений** (защита от абуза). Когда таймер истекает, вложения исчезают
и в ящике спавнятся случайные предметы, которые забирают перетаскиванием в инвентарь (нужно свободное
место); по завершении круга открывается модальное окно с итогами — сколько предметов и денег вложено,
сколько получено и разница. Таймер зависит от суммы вложений:
менее 100 000 — **15 секунд**, от 100 000 до 250 000 — **30 секунд**, свыше 250 000 — **60 секунд**;
чем выше сумма вложений, тем выше шанс редкого дропа (вплоть до красного) и тем больше предметов
выпадает. Дроп, которому не хватило клеток ящика, ждёт свободного места. REST:
GET /api/santa, POST /api/santa/sacrifice, POST /api/santa/take.

## Сеты

Страница «Сеты» (/sets) — 9 тематических сетов по 5 предметов каталога. Предметы ставятся
в витрину (запираются до снятия), заполненный сет даёт постоянные бонусы: торговец +5%,
личное раскрытие в лотах, скидка самовыкупа 25% и +10 с на ставки, комиссия барахолки −2 п.п.,
+2 дня жизни лотов, +10% стартового кэша и «слухи» о скрытых предметах, суточная трансмутация
(3 белых → зелёный, 10% шанс синего). Часть бонусов (крафт, экспедиции, доходы зала) помечена «скоро».
REST: GET /api/hideout, POST /api/hideout/place|remove|transmute.

## Особые карточки, крафт и рынок карточек

Особые карточки — расходник партии: анализаторы раскрывают редкость скрытых предметов стола, и
подсказки видит только владелец. **Одна карточка за раунд торгов** — правило проверяет сервер,
счётчик сбрасывается в начале каждого раунда.

- **Крафт билета.** В разделе «Сеты» есть мастерская: три предмета **одного качества** обмениваются
  на «Пыльную вазу» — билет колеса фортуны. Цвета не смешиваются, в обмен идут три самых дешёвых
  предмета выбранного качества, а готовые билеты в обмен не попадают.
- **Рынок карточек.** Карточки продаются и покупаются на барахолке на тех же условиях, что предметы:
  свободная цена, срок жизни лота, комиссия дома. `GET /api/market/cards`, `POST /api/market/cards/list`,
  `/buy`, `/cancel`.
- **Боты.** Играют карточками по тем же правилам (не больше одной за раунд, выбирают самый сильный
  анализатор) и, когда запас кончается, покупают их на общем рынке — а если предложений нет,
  крафтят билет из своих предметов и крутят колесо.

## Итоги партии

Экран итогов показывает **результат партии**, а не нетто-состояние: раньше в таблице были
«наличные + инвентарь», из-за чего победитель с профитом 100 000 выглядел как владелец 750 000,
а проигравшие — как люди с деньгами, хотя каждый потерял вход.

Теперь на экране:

- **главная цифра** — итог партии со знаком и цветом (зелёный / красный), с подписью «заработано»
  или «потеряно»;
- **разбор расчёта** — ценность стола, ваша ставка, компенсация, плата за вход и итог, построчно;
- **состояние на финише** — сколько осталось наличными, сколько в инвентаре и сколько пришло
  предметами;
- **места** — у каждого игрока итог партии, ниже мелким шрифтом вложения и общее состояние,
  у победителя торгов помечено «выиграл торги».

Итог = (наличные + инвентарь на финише) − (то же на старте). Вход и ставка уже вычтены, полученные
предметы учтены по номиналу, поэтому для победителя сходится с «ценность стола − ставка − вход».

## Анимации (GSAP)

Весь интерфейс анимирован через GSAP. Общий модуль `apps/web/src/lib/animations.ts` — единственное
место, где настраивается GSAP и живут переиспользуемые движения: `popIn`, `staggerIn`, `countUp`,
`shake`, `pulse`, `flash`, `flyTo`, `flipTransition`. Там же проверка `prefers-reduced-motion`:
при системной настройке «уменьшить движение» анимации не запускаются.

Что анимировано:

- **лобби** — карточки залов выезжают каскадом, свечение в цвет сословия при наведении, тряска при
  нехватке денег, полоса прогресса до следующего ранга наполняется, баннер повышения ранга с салютом;
- **вход в партию** — плата за вход «вылетает» и подсвечивается, кнопка мягко появляется;
- **стол** — волна появления клеток и раскрытие каждого предмета: переворот плюс вспышка цветом
  его редкости;
- **торги** — смена раунда, каскадное вскрытие ставок, вспышка объявления победителя (красная при
  сгоревшем столе);
- **деньги** — любое изменение суммы «набегает» счётчиком и вспыхивает зелёным при начислении и
  красным при списании (шапка, партия, соперники, итоги);
- **инвентарь** — FLIP-перелёт предметов при автосортировке, продаже и выставлении лота; предмет
  «испаряется» при продаже и «уезжает» при листинге; каскадный пульс по найденным через поиск;
- **колесо фортуны** — рывок сцены на старте, затухание, «щелчок» стрелки и вспышка выигравшего
  сектора;
- **сеты** — постановка предмета в витрину с подсветкой активации, вспышка при трансмутации;
- **Тайный Санта** — вспышка ящика при вложении (сильнее при наборе минимума), каскадный «вылет»
  нового дропа;
- **барахолка и лидеры** — каскадное появление строк, лот «улетает» при покупке;
- **тосты** — въезжают снизу, живут с полоской-таймером, плавно сдвигают стек;
- **лобби партии** — новые игроки въезжают, стол проявляется при старте, таймер пульсирует и
  краснеет на последних 10 секундах, журнал подсвечивает новые записи по типу события;
- **итоги партии** — строки влетают каскадом, первое место подсвечивается, при своей победе
  экран коротко «празднует»;
- **карточки в партии** — применение анализатора со вспышкой, каскад при загрузке;
- **шапка и вход** — навигация мягко въезжает, карточка входа и кнопки появляются каскадом;
- **админка** — панели и журнал операций появляются каскадом.

## Залы и прогрессия

Игра построена как казино: три сословия с **фиксированной платой за вход** и **предопределённой
ценностью стола**, которая разыгрывается до начала партии и не зависит от взносов игроков.

| Зал | Вход | Ценность стола | Открывается |
|-----|------|----------------|-------------|
| 🥉 Медный | 10 000 | 80 000 – 180 000 | с начала |
| 🥈 Серебряный | 100 000 | 520 000 – 1 250 000 | ранг «Игрок» |
| 🥇 Золотой | 1 000 000 | 6 000 000 – 14 000 000 | ранг «Мастер» |

**Прогресс игрока** считается по накопленному итогу партий за карьеру (не по текущему балансу —
поэтому проигрыши не откатывают ранг): Новичок → Любитель → Игрок → Мастер → Легенда. Ранг
открывает старшие залы, а полоса прогресса показывает, сколько осталось до следующего.

**Серия побед** даёт надбавку к призовым: +5% за каждую победу сверх первой, максимум +25%.
Платит зал из банка дома. Проигрыш обнуляет серию, но лучшая остаётся в профиле.

Прогресс виден в лобби (ранг, полоса, серия) и в панели торгов (текущая серия и её процент),
а повышение ранга отмечается отдельным баннером с анимацией.

## Экономика

Экономика построена так, чтобы **копить было осмысленно, а риск — оправдан**:

- **Медианный стол стоит около 3 млн**, но дешёвые столы (400–600к) — обычное дело,
  а дорогие (6–9 млн) — редкий джекпот, ради которого стоит копить и переплачивать;
- **Обычный исход партии — минус вступительный взнос** (30–100к): кто не выиграл лот,
  теряет только его. Медианный профит за партию ≈ −60к, а победитель лота уходит
  в заметный плюс. Это и создаёт риск;
- **Мгновенная продажа торговцу даёт 70% номинала** (`VENDOR_RATE`). Это плата за
  удобство: барахолка выгоднее (лоты уходят по 105–135% номинала), но требует времени.
  Раньше торговец платил 100%, и барахолка была не нужна — 1128 лотов против 12 сделок;
- **Банк дома не печатает деньги.** Стартовый капитал и покупки у торговца проходят
  только при достаточном балансе банка (`houseCanAfford`). Если банк пуст, новые
  игроки входят без наличных, а торговец отказывается покупать — пополнить банк
  можно в админ-панели. Раньше банк молча ушёл в минус на 65 млн;
- **Переплата всегда невыгодна.** Компенсация проигравшим ограничена так, что
  суммарные выплаты не могут превысить ставку победителя. Иначе при 3+ соперниках
  (по 10% от минуса каждому) переплата окупалась за счёт банка — это была прямая
  печать денег.

## Боты (живой онлайн)

Чтобы игра не ощущалась пустой, на сервере работает **парк самостоятельных ботов** — это обычные
аккаунты-игроки, которыми управляет ИИ. Боты запускаются вместе с сервером и подключаются к нему
**по обычному Socket.IO с JWT**, то есть видят ровно тот же снимок состояния, что и человек:
раскрытые клетки, ожидаемую стоимость, свой инвентарь и свои карточки. Доступа к внутреннему
состоянию движка (порядок раскрытия, скрытые предметы, генератор случайных чисел, чужие слепые
ставки) у них нет — это закреплено тестом `bots-fairness.test.ts`.

**Характеры.** У каждого бота один из шести психологических архетипов, который влияет на все
решения в торгах:

| Характер | Психотип | Поведение |
|---|---|---|
| Азартный | риск-сикер | перебивает, редко пасует, легко переплачивает |
| Осторожный | риск-эйверс | ставит мало, пасует при перегреве цены |
| Расчётливый | прагматик | считает ожидаемую стоимость стола |
| Жадный | максимизатор | торгуется до предела, не любит уступать |
| Мстительный | эмоциональный | после проигрыша поднимает агрессию |
| Новичок-паникёр | тревожный | путается в оценке, ставит круглые суммы |

Характер задаёт склонность к риску, порог паса, ошибки в оценке, темп принятия решений и реакцию
на проигрыши. Он сохраняется в БД, поэтому бот не «меняет личность» между перезапусками.

**Человеческое поведение.** Боты думают 1.5–12 секунд перед ставкой (пауза зависит от характера),
ставят круглые суммы и «+1» поверх лидера, иногда импульсивно пасуют, болтают за столом, а между
партиями живут своей жизнью: продают хлам торговцу, выставляют лоты на барахолке, покупают
выгодные предложения, крутят колесо за «Пыльные вазы», применяют анализаторы и усилители, ставят
предметы в сеты и вкладываются в «Тайного Санту». Бот играет сессиями по 1–4 партии, затем
«уходит по делам» на паузу и возвращается — онлайн получается неровным, как у людей.

**Цель — топ-10.** Каждый бот стремится попасть в топ-10 богатейших (счёт = наличные + инвентарь).
Отставая, он играет агрессивнее; попав в топ — бережёт позицию. Никаких читов и выдач «сверху»:
бот стартует с тем же набором новичка, платит комиссии, ждёт таймеры и получает бонусы сетов.

**Лобби и SLA.** Бот может сам создать комнату и нажать «Я готов/а», поэтому четыре бота играют
между собой без участия человека. Когда «Играть» нажимает живой игрок, его комнату немедленно
дозаполняют боты из резерва — **ожидание не должно превышать 30 секунд**. Парк держит резерв
свободных ботов (`BOT_RESERVE_ROOMS`) именно для этого, а боты без наличных не выпадают из
подбора навсегда: они продают предметы торговцу и возвращаются в игру.

**Метрики.** `GET /api/bots/stats` отдаёт состояние парка (сколько играет, сколько в лобби,
сколько свободно), разбивку по характерам и метрики ожидания (медиана, p95, максимум, соблюдение
SLA). Проверка SLA на живой игре: `npm run bots:sla` (по умолчанию 5 заходов, `RUNS=15` — больше).

## Банк дома и админ

У дома есть внутренний аккаунт-банк: туда идут доходы партий (плата за призовые лоты и самовыкупы)
и комиссия барахолки 5%; оттуда платятся покупки торговца (предметы переходят в собственность дома),
стартовые капиталы новичков и админские выплаты. Все проводки пишутся в журнал.

Чтобы стать админом, укажите свой email в ADMIN_EMAILS и войдите заново —
в навигации появится пункт «Админ» (/admin): баланс и журнал банка, пополнение банка,
выплаты игрокам по email и выставление предметов дома на барахолку.
REST: GET /api/admin/bank, POST /api/admin/bank/deposit, POST /api/admin/bank/transfer,
POST /api/admin/market/list, POST /api/admin/items/grant (выдача предмета из каталога — только для админов).

## Библиотека

Страница «Библиотека» (/library) — обучающий помощник игрока: разделы «Правила игры», «Основы»,
«Особые карточки» (комплекты, магазин, колесо фортуны, шансы), «Предметы и их описания» (полный
каталог с описаниями, генерируется автоматически из каталога), «Барахолка и торговец», «Сеты» и
«Банк дома и админ». Поиск работает от 2 символов: совпадения подсвечиваются жёлтым в тексте,
найденные предметы получают золотую рамку, остальные затемняются.

Правило (см. RULES.md): новые фичи, предметы, механики и изменения должны отражаться в библиотеке
одновременно с их реализацией; каталог предметов и сеты выводятся автоматически, поэтому описания
новых предметов и сетов добавляются прямо в их определения (packages/shared).

## API (кратко)

- REST: POST /api/auth/dev-login, POST /api/auth/password-login (вход по паролю, аккаунт shlepafloppa),
  GET /api/auth/google[/callback], GET /api/me, GET /api/rooms,
  GET /api/profile/:id[/history] (профиль игрока и его история матчей: вложения и разница),
  GET /api/game/:id (детализация матча: участники и предметы призового стола),
  GET /api/market, POST /api/market/list|buy|cancel, POST /api/items/sell (продажа торговцу),
  GET /api/shop, POST /api/shop/spin (колесо фортуны), GET /api/cards, POST /api/cards/amplify;
- Socket.IO (JWT в handshake.auth.token): room:create, room:join, room:start, game:place,
  game:remove, game:ready, game:bid, game:sync, card:use (применение анализатора);
  сервер шлёт полный снимок состояния событием state.

## Ограничения текущей версии

- Один аккаунт — одна одновременная партия (предметы блокируются на время игры);
- При перезапуске сервера незавершённые партии сбрасываются (предметы возвращаются, деньги не теряются);
- Google OAuth требует реальных учётных данных — без них используйте dev-вход.
